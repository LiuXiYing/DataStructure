## 二、二叉树的二叉链表定义

### 2.1 节点与空树

二叉树是每个节点**至多两个孩子**（左孩子 `lc`、右孩子 `rc`）的树形结构。本次采用与课堂示例完全相同的二叉链表定义，一个节点就是三个成员：

| 成员 | 含义 |
| :--- | :--- |
| `data` | 保存的元素，类型为 `T` |
| `lc` | 指向左孩子的指针，无左孩子时为 `nullptr` |
| `rc` | 指向右孩子的指针，无右孩子时为 `nullptr` |

树本身不需要单独的"树对象"：**指向根节点的指针就代表整棵树**，根指针为 `nullptr` 即空树。判断某节点是不是叶子，就看 `lc` 和 `rc` 是否都为 `nullptr`。

### 2.2 手动创建的三步

课堂示例 `BinTreeTraversal.cpp` 用三步创建一棵树，本次在 `main` 中也按这个思路写：

1. **逐个 `new` 出节点**：`Node* A = new Node;`。默认构造函数会把 `lc`、`rc` 置为 `nullptr`，`data` 保持默认值。
2. **给每个节点的 `data` 赋值**：`A->data = 'A';`。
3. **指定父子关系**：`A->lc = B; A->rc = C;`。叶子节点不必再显式赋空，但像课堂示例那样显式写出便于观察。

创建完成后，只需要保存**根节点的指针**，之后四种遍历都从根指针出发。

## 四、学生任务二：三种递归遍历

### 4.1 递归的图景

任何非空二叉树都可以拆成三部分：**根节点、左子树、右子树**；左、右子树本身又是二叉树。所谓遍历，就是给"访问根"这件事在"遍历左子树""遍历右子树"之间安排一个位置：

| 遍历 | 顺序 | 口诀 |
| :--- | :--- | :--- |
| 先序 preorder | 根 → 左 → 右 | 先访问根，再各自遍历两棵子树 |
| 中序 inorder | 左 → 根 → 右 | 左子树全部处理完才轮到根 |
| 后序 postorder | 左 → 右 → 根 | 两棵子树都处理完才轮到根 |

三种遍历的递归实现**只差访问根节点那几行语句的位置**；空树（`root == nullptr`）是唯一的递归出口，直接返回。

### 4.2 学生任务


要求如下：

- "访问"节点统一为 **`std::cout << root->data << ' ';`**：输出该字符后跟一个空格，不输出标签、换行或其他说明——标签和换行由教师提供的输出框架负责。
- 不使用循环、栈、队列或任何容器模拟递归，不把节点收集到数组再输出。
- 不写死任何序列：函数必须对**任意形状**的二叉树都正确，不能只对本次指定的树或某棵特殊树成立，不允许在函数体内直接输出固定的字符序列。
- 参数可能为空指针（空树），此时不输出任何内容，正常返回。

## 五、学生任务三：层次遍历

### 5.1 思路：用队列维持"从上到下、从左到右"

层次遍历按**深度**逐层访问节点，同一层内从左到右。递归写法不方便表达"层"的概念，改用**先进先出队列**：

1. 空树直接返回；否则根节点入队。
2. 队列非空时，取出队头节点并访问（输出）。
3. 依次把它的**左孩子、右孩子**（如果存在）入队。
4. 回到第 2 步，直到队列为空。

队列保证：第 `k` 层的节点全部出队并访问之后，第 `k+1` 层的节点才按从左到右的顺序出现在队头。课堂示例 `levelOrder` 就是这个写法，本次照此实现。

### 5.2 学生任务

补全：

```cpp

```

- 使用 `std::queue<Node*>`（文件顶部已包含 `<queue>`），只做 `push`、`front`、`pop`、`empty` 操作。
- 先判空；出队前检查队列非空；孩子入队前检查孩子存在。
- 访问即输出，格式与三种递归遍历相同：`std::cout << p->data << ' ';`。
- 不用递归代替队列，不一次输出一整层，也不写死序列。

## 六、理解与验证

以下均根据自己的代码、运行结果和手工推演填写，不保留"填写"等占位文字。

### 6.1 接口映射

| 函数 | 递归出口 / 前提 | 访问节点（输出）的时机 | 辅助数据结构 |
| :--- | :--- | :--- | :--- |
| 手动建树（main 中） | 无递归、不设出口；前提是先由构造函数把 `lc`、`rc` 置为 `nullptr` 再连线 | 建树全程不输出，只 `new`、赋 `data`、连接孩子指针 | 无（仅若干节点指针与根指针 `root`） |
| `preorder()` | `root == nullptr` 时直接返回 | 进入左、右两次递归之前输出根 | 无（仅系统递归栈） |
| `inorder()` | `root == nullptr` 时直接返回 | 左子树递归返回之后、右子树递归之前输出根 | 无（仅系统递归栈） |
| `postorder()` | `root == nullptr` 时直接返回 | 左、右两次递归全部结束之后输出根 | 无（仅系统递归栈） |
| `levelOrder()` | `root == nullptr` 时直接返回；出队前判队列非空、入队前判孩子非空 | 节点出队时输出它的 `data` | `std::queue<Node*>` |

1. 为什么三种递归遍历的函数体只差"访问根"语句的位置？如果把这句去掉，三个函数还有什么区别？

   > 三种遍历共用同一副递归骨架：先判空出口，再依次递归左、右子树，三者只在"什么时候真正处理根节点"上不同，所以函数体的差别仅仅是访问根那一行的位置。若把访问语句去掉，三个函数体就完全相同——都只是从根出发把整棵树空跑一遍，对任何树都不再有任何输出，彼此毫无区别。

2. 默认构造函数把 `lc`、`rc` 置空，这一步对手动建树有什么意义？如果 `new` 出来的节点两个孩子是随机值，四种遍历会出什么问题？

   > 默认构造把两个孩子指针置空，使每个新节点一出生就是"叶子"状态；手动建树只需给确实存在的孩子连线，其余位置（叶子、`C` 的左孩子）保持 `nullptr`，递归遍历才有可靠的终止条件。若孩子指针是随机值，遍历就会沿野指针访问非法内存：可能输出乱码、崩溃或递归无法终止（未定义行为）；`destroyTree` 也会 `delete` 无效指针，造成非法释放。

3. `destroyTree` 为什么按"先左右子树、后根"的顺序释放？这与哪种遍历对应？若先 `delete` 根再递归释放子树，会发生什么？

   > 只有先保留父节点，才能沿它的 `lc`、`rc` 找到子树，所以要等左右子树都释放完，最后才 `delete` 根；这正与后序遍历（左-右-根）对应。若先 `delete` 根再递归，就必须从已释放的内存里读 `lc`、`rc`（悬垂指针，use-after-free），属于未定义行为：可能崩溃、重复释放或释放到错误地址，而且子树的指针已随根一起丢失，造成内存泄漏。

### 6.4 时间与空间

按本实验实现分析；视一次输出、一次入队出队为常数开销。令 `n` 为节点总数，`h` 为树高，`w` 为树的最大宽度（同一层最多的节点数）。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| 三种递归遍历各自的时间 | O(n) | 每个节点恰好被访问一次、每个空孩子被判断一次，总工作量与节点数 n 成正比 |
| 三种递归遍历各自的辅助空间（递归栈） | O(h) | 任一时刻栈上只保留从根到当前节点的一条路径，最长为树高 h |
| 层次遍历的时间 | O(n) | 每个节点恰好入队一次、出队一次、访问一次，均为常数开销 |
| 层次遍历的辅助空间（队列） | O(w) | 队列中同时存放的只是尚未访问的某一层节点，最多为最大宽度 w |
| `main` 中手动创建 6 个节点的时间 | O(1) | 6 次 `new` 加常数次赋值与连线，是固定工作量，与规模无关 |

说明：空间表达式需能解释空树、单节点树的情况；指出什么形状的树会让递归深度达到 `n`、什么形状的树让队列长度达到 `n`。空树只进入函数一次即返回，递归栈深度为 1（常数），队列长度为 0；单节点树递归栈深度为 1、队列长度为 1。当树退化成单支链（每层只有一个节点，如全是左孩子的链）时 h = n，递归深度达到 `n`；当树又矮又宽时队列最长，完全二叉树的最宽层（最后一层）约有 `n/2` 个节点同时排队，队列长度达到 `n/2`，即 O(w) 为 O(n) 量级。

### 6.5 讨论与猜想

1. 把 `preorder` 中"访问根"的语句从两次递归**之前**移到**之后**，得到的是哪种遍历？若移到两次递归**中间**呢？

   > 移到两次递归**之后**得到后序遍历（左-右-根）；移到两次递归**中间**（先递归左子树、再访问根、最后递归右子树）得到中序遍历（左-根-右）。

2. 层次遍历为什么必须用队列？如果把队列换成栈，得到的输出会具有什么特点？

   > 层次遍历要求先进先出：先被访问的节点，其孩子必须排在其后的节点访问，队列恰好保证第 k 层的节点全部出队之后，第 k+1 层才按从左到右的顺序出队。若换成栈，后进先出会让最近入队的孩子先出队，输出变成沿一条分支深入、再回溯换分支的深度优先序列——对本次这棵树，若先压右孩子再压左孩子，输出恰好是先序 `A B D E C F`，逐层的顺序完全丢失。

3. 先序遍历与层次遍历都最先访问根。它们的序列什么时候相同？各举一棵树说明。

   > 当树的形状恰好使"沿分支深度优先"的先序等于"逐层从左到右"的层次顺序时两者相同。例一：每层只有一个节点的单链树（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`），先序与层次都是 `A B C`；例二：深度为 1 的树（`A` 的左、右孩子是 `B`、`C`），先序与层次也都是 `A B C`。形状稍复杂就会不同，如本次指定的树，先序是 `A B D E C F`，层次是 `A B C D E F`。

4. 已知一棵二叉树的先序序列和中序序列，能否唯一确定这棵二叉树？若只给先序序列呢？分别用一个具体例子说明。

   > 先序加中序可以唯一确定（前提是元素互异）：先序的第一个元素是根，在中序中定位根，中序里根左边整段是左子树、右边整段是右子树，再对两段递归切分。例：先序 `A B C`、中序 `B A C`，得根 `A`，左子树只剩 `B`，右子树只剩 `C`，树唯一确定。只给先序不行：先序 `A B C` 至少对应三棵不同的树——`A` 只有左链（`A` 的左孩子是 `B`，`B` 的左孩子是 `C`）、`A` 只有右链、以及 `A` 的左孩子是 `B` 且右孩子是 `C`。

5. 手动建树为 6 个节点写了多少行创建与赋值代码？如果是一棵 1000 个节点的树，这种方法还现实吗？结合"同样的元素，有的树查得快、有的树查得慢"，猜想要让建树和查找高效，下一阶段会学习什么结构？

   > 我的建树代码约 25 行：6 行 `new`、6 行 `data` 赋值、12 行孩子连线、1 行 `root` 赋值。按"每个节点约 3 行"估算，1000 个节点要写三千行左右，既冗长又极易连错，完全不现实（也无法从数据批量生成）。结合"同样元素、树形不同则查找快慢不同"，要让建树和查找都高效，下一阶段应会学习（平衡的）二叉查找树／搜索树（如 AVL 树、红黑树、B 树等），用有序且平衡的结构把树高压到 O(log n)，查找、插入、删除都快。
