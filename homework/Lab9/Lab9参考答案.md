# Lab9 参考答案：队列、循环分配器与银行服务模拟

本答案对应同目录的 [Lab9.md](Lab9.md)。题目代码保留六处学生 TODO；下面给出对应实现、第六节的参考作答及参考实现的实际运行结果。循环分配器采用两个参数，直接使用 `std::cout` 输出服务对象。

## 一、六处 TODO 的参考实现

### 1. queue.h：入队、出队与访问队首

将以下三个函数分别填入 `queue.h` 中对应的位置，类的声明保持不变。

```cpp
template <typename T>
void Queue<T>::enqueue(const T& e) {
    // 链表末端作为队尾，尾插负责接链并增加元素计数。
    this->insertAsLast(e);
}

template <typename T>
T Queue<T>::dequeue() {
    // 调用者保证非空；删除首个真实节点，按值返回被删除的元素。
    return this->remove(this->first());
}

template <typename T>
T& Queue<T>::front() {
    // 只访问数据，不删除节点；返回引用以便直接修改队内元素。
    return this->first()->data;
}
```

`this->` 用于明确访问依赖于模板参数的基类成员。链表已经负责节点的创建、连接、计数和释放，队列只需选择合适的操作位置。

### 2. round_robin.cpp：循环分配器

```cpp
void roundRobin(Queue<char>& Q, int rounds) {
    for (int i = 0; i < rounds; ++i) {
        // 空队列没有可服务的对象，不能继续出队。
        if (Q.empty()) break;
        // 出队会删除原节点，因此保存字符值，而不是节点内元素的引用。
        char e = Q.dequeue();
        std::cout << e << ' ';
        // 服务过的对象排到队尾，下一次由原来的第二个对象接受服务。
        Q.enqueue(e);
    }
}
```

一次分配只服务一个对象。每次操作结束后，队列元素总数不变；`rounds == 0` 时不输出，也不改变队列。测试代码负责收集标准输出，函数中不需要额外的输出流参数。

### 3. bank.cpp：选择最短队列

```cpp
int bestWindow(Queue<Customer> windows[], Rank nWin) {
    int best = 0;  // nWin > 0，先把编号最小的窗口作为候选。
    for (Rank i = 1; i < nWin; ++i) {
        // 只在严格更短时更新；同长则保留此前编号较小的窗口。
        if (windows[i].size() < windows[best].size()) {
            best = i;
        }
    }
    return best;
}
```

比较的是人数，包括正在接受服务的队首顾客；不比较剩余服务时间，也不能找到第一个更短的队列就提前返回。

### 4. bank.cpp：推进一个时间单位

```cpp
int serveOneTick(Queue<Customer> windows[], Rank nWin) {
    int finished = 0;
    for (Rank i = 0; i < nWin; ++i) {
        if (windows[i].empty()) continue;
        // front() 返回引用，这里直接修改保存在队列中的顾客。
        --windows[i].front().time;
        if (windows[i].front().time == 0) {
            windows[i].dequeue();
            ++finished;
        }
        // 当前窗口本轮服务结束，不再处理刚成为队首的下一位顾客。
    }
    return finished;
}
```

在队顾客的 `time` 必须为正，才能安全递减无符号数。一次调用中，每个窗口最多完成一位顾客；多个窗口可以各自完成一位，返回值是本轮完成数。

## 二、第六节参考作答

### 6.1 链表与队列接口

| 队列操作 | 操作位置 | 复用的 List 接口或节点成员 | 返回值的含义 |
| :--- | :--- | :--- | :--- |
| `enqueue(e)` | 队尾，即链表末端 | `insertAsLast(e)` | 无返回值；元素的副本加入队尾 |
| `dequeue()` | 队首，即首个真实节点 | `first()`、`remove(p)` | 被删除的队首元素的值 |
| `front()` | 队首，即首个真实节点 | `first()->data` | 队首元素的引用，可用于读取和修改；节点仍在队内 |

**1. 空表与哨兵。** 空表中 `header->succ == trailer`，`trailer->pred == header`，`header->pred` 和 `trailer->succ` 都是 `nullptr`。两个哨兵不计入 `size()`，所以空表大小为 0。第一次插入仍是在两个有效节点之间接入新节点；删除唯一的真实节点时，让它的前驱、后继互相连接，恰好恢复两个哨兵相连的空表，因此不需要单独的边界分支。

**2. 删除、清空与析构。** `delete p` 后节点内的 `data` 已不再可访问，因此 `remove` 必须先保存元素，释放节点后再按值返回保存的内容。`clear()` 只删除真实节点并保留哨兵，链表还能继续使用；析构函数先调用 `clear()`，再释放两个哨兵。`Queue` 复用 `List` 的插入和删除接口，销毁队列时也会执行基类析构，因此不需要自己管理 `new`、`delete`。

**3. 引用与返回值。** `front()` 不删除节点，返回引用可让调用者直接修改队内元素；`dequeue()` 会删除节点，若返回其中元素的引用就会产生悬空引用，所以返回元素值。仅在队尾入队不会移动或删除原队首节点，保存的队首引用仍有效；删除该队首后，原引用立即失效，不能再使用。

### 6.2 手工追踪循环分配器

初始队列为 `A → B → C`，进行 5 次分配。

| 分配次数 | 本次服务对象 | 出队后、重新入队前的队列 | 重新入队后的队列 |
| :---: | :---: | :--- | :--- |
| 1 | A | B → C | B → C → A |
| 2 | B | C → A | C → A → B |
| 3 | C | A → B | A → B → C |
| 4 | A | B → C | B → C → A |
| 5 | B | C → A | C → A → B |

- 服务顺序为 `A B C A B`。A、B 各获得 2 次服务，C 获得 1 次；再分配一次将服务 C。
- “循环”来自每次服务后将对象重新入队。普通 FIFO 队列就能形成轮流服务的顺序，不要求底层链表首尾相连；如果忘记重新入队，对象服务一次后就会永久离开，队列最终为空。
- 初始队列为空时没有可服务的对象，即使 `rounds > 0` 也应立即结束，否则出队会误操作哨兵并破坏链表。

### 6.3 银行模拟观察与手工追踪

以下为固定模拟 `now == 2` 时，三个断点处应观察到的状态。它们根据执行顺序推演，并由固定时间线测试核对；不是 CLion 实际断点操作记录。队列中的数字表示剩余服务时间。

| 暂停位置（该行执行前） | 窗口 0 队列 | 窗口 1 队列 | 本轮已发生的事件 |
| :--- | :--- | :--- | :--- |
| A | 1 | 1 | 已取得本轮到达顾客所需时间 `time = 4`，尚未选窗口、入队或服务 |
| B | 1 → 4 | 1 | 两窗口入队前人数相同，选择窗口 0；新顾客已入队，本轮尚未服务 |
| C | 4 | 空 | 两个旧队首各接受 1 单位服务并离开；窗口 0 的新队首尚未接受服务 |

- B 处 `chosen == 0`。选择依据是本轮新顾客入队之前、各窗口本轮服务之前的人数；此时两个窗口各有 1 人，同长时选编号较小的窗口。
- C 处 `finished == 2`。窗口 0 本轮的服务机会已经用于旧队首，旧队首离开后不能接着给新队首减时间，因此新队首剩余时间仍为 4。C 行尚未执行，累计 `served` 要在执行 `served += finished` 后才加上本轮完成数。

另一个场景：1 个窗口，营业 4 个时间单位，到达表为 `{2, 1, 3, 0}`。

| `now` | 本时刻到达 | 本轮服务结束后的队列（队首 → 队尾） | 本轮离开的顾客 |
| :---: | :--- | :--- | :--- |
| 0 | A，需要 2 单位 | A:1 | 无 |
| 1 | B，需要 1 单位 | B:1 | A |
| 2 | C，需要 3 单位 | C:3 | B |
| 3 | 无 | C:2 | 无 |

最终统计为 `arrived = 3`，`served = 2`，`remaining = 1`，满足 `3 = 2 + 1`。营业结束时 C 还需 2 个单位服务，模拟立即停止，不再把 C 服务完。

### 6.4 时间与空间

按题目约定，元素复制、单个节点的申请和释放视为常数开销。`n` 为队列元素数，`k` 为实际分配次数，`w` 为窗口数，`t` 为模拟时间单位数，`m` 为同时在队顾客总数的最大值。

| 项目 | 复杂度 | 简要理由 |
| :--- | :--- | :--- |
| `enqueue()`、`dequeue()`、`front()` 各自的时间 | 各为 O(1) | 哨兵可以直接定位首尾，只访问或修改常数个指针和数据 |
| 一个有 `n` 个元素的队列占用的空间（含哨兵） | O(n + 1) | `n` 个真实节点，加两个哨兵及固定管理成员；空队列也占常数空间 |
| 非空队列完成 `k` 次循环分配的总时间 | O(k + 1)，`k > 0` 时可写 O(k) | 每次出队、输出一个字符和入队均为常数开销；零次也有常数判断开销 |
| `roundRobin` 除已有队列、输出记录外的辅助空间 | O(1) | 仅使用循环变量和一个字符，不建立随分配次数增长的容器 |
| `bestWindow` 的时间 | O(w) | 扫描所有窗口，`size()` 为 O(1) |
| `serveOneTick` 的时间 | O(w) | 每个窗口检查一次，每个非空窗口最多处理一个队首 |
| 银行模拟 `t` 个时间单位的主循环总时间（忽略输出成本） | O(tw)，零轮时仅有常数判断开销 | 每轮服务必扫描 `w` 个窗口；有顾客到达时选择窗口也扫描 `w` 个窗口 |
| 银行窗口数组与全部队列的峰值空间 | O(w + m) | `w` 个队列对象与 `2w` 个哨兵占 O(w)，最多 `m` 个真实顾客节点占 O(m) |

主循环时间不包含窗口数组的初始化和结束后的析构。即使所有窗口都空闲，仍要逐个检查窗口；即使 `m == 0`，窗口数组和每个队列的哨兵也仍需 O(w) 空间。

### 6.5 两个应用的联系与区别

**1. 出队时机与 FIFO。** 循环分配器每次先将队首出队，服务一次后把同一对象重新排到队尾，使其他对象获得下一次机会；银行模拟只在队首剩余服务时间减为 0 时出队，顾客完成服务后不再入队。前者用 FIFO 保持轮流服务的顺序，后者用 FIFO 保持同一窗口顾客先到先服务的顺序。

**2. 局部副本与队内元素。** `Customer c = Q.front();` 把队首复制到局部变量，修改 `c.time` 不会改变队内顾客；`Q.front().time` 则直接访问队内元素。若每轮都只给局部副本减 1，队内剩余时间不会持续减少，原本需要多于 1 个时间单位的顾客就无法正常完成服务。

**3. 人数少不一定等待短。** 例如窗口 0 只有一位顾客，但还需 10 个时间单位；窗口 1 有两位顾客，却各只需 1 个时间单位，新顾客排在窗口 1 后面反而更早开始接受服务。本实验仍按人数选择，因为题目和教材模型明确使用队列长度作为分配依据，不要求累计服务时长。

**4. 释放内存不等于完成服务。** 固定模拟结束时剩余顾客还有 1 个单位服务未完成，析构释放节点只是清理内存，不能增加 `served`。守恒关系描述营业结束时顾客的状态，所以必须在删除队列之前统计 `remaining`；队列销毁后不能再读取人数，也不能将已释放的顾客算作已服务。
